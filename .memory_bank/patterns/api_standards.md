# API Standards: Stochastic Process Visualizer

## 1. Общие принципы
- **RESTful** – используем HTTP методы и статус коды по назначению.
- **JSON** – единственный формат запросов и ответов (кроме скачивания CSV, которое генерируется фронтендом из полученных данных, либо отдельный эндпоинт, но в MVP не требуется).
- **Версионирование** – через URL-префикс: `/api/v1/...`.
- **Идемпотентность** – POST-запросы на генерацию не идемпотентны (каждый раз новая траектория), но это допустимо.

## 2. Базовые требования

### 2.1 URL структура
- Все эндпоинты начинаются с `/api/v1/`.
- Существительные во множественном числе (если ресурс коллекция). В нашем случае – один эндпоинт:
  - `POST /api/v1/generate`

### 2.2 HTTP методы
| Метод | Использование |
|-------|---------------|
| `POST` | Генерация траектории (создание нового ресурса) |
| (в будущем) `GET` | Получение предопределённых примеров или метаданных |

### 2.3 Заголовки
- `Content-Type: application/json` для запросов и ответов.
- Для ответов с ошибками – также `application/json`.
- (Опционально) `Accept: application/json` – клиент может отправлять.

## 3. Формат запросов и ответов

### 3.1 Эндпоинт: `POST /api/v1/generate`

**Тело запроса (JSON)** – Pydantic модель:
```json
{
  "process_type": "wiener | ou",
  "T": 1.0,
  "N": 500,
  "X0": 0.0,
  "theta": 1.0,      // только для ou
  "mu": 0.0,         // только для ou
  "sigma": 1.0       // только для ou
}

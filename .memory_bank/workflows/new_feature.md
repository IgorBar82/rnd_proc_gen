# Процесс разработки новой фичи

## 1. Планирование
- [ ] Создать ветку от `develop` по шаблону `feature/TICKET-NUMBER-short-description`.
- [ ] Ознакомиться с бизнес- и технической спецификацией в `../specs/`.
- [ ] Согласовать ожидаемое поведение с Product Owner или тимлидом.

## 2. Разработка
- [ ] Реализовать функциональность, следуя правилам из **[guides/coding_standards.md](../guides/coding_standards.md)**.
- [ ] Добавить или обновить тесты для новой логики.
- [ ] Запустить общий набор тестов (например, `pytest`) и убедиться, что изменений не сломано.
- [ ] Если требуется новая зависимость, обновить `.memory_bank/tech_stack.md`.

## 3. Проверка
- [ ] Проверить поведение новой функции вручную или через автоматические тесты.
- [ ] Убедиться, что документация и спецификации актуальны.

## 4. Завершение
- [ ] Обновить статус задачи в **[../current_tasks.md](../current_tasks.md)**.
- [ ] Подготовить Pull Request с описанием изменений и ссылками на спецификации.
- [ ] Закоммитить изменения согласно консенсусу по Git-сообщениям.

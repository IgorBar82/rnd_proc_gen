# CLAUDE.md

0. При выполнении любой задачи начинай с чтения файла .memory_bank/README.md

Поведенческие рекомендации для снижения типичных ошибок LLM при написании кода. При необходимости объединяйте с проектными инструкциями.

**Компромисс:** Эти рекомендации отдают приоритет осторожности, а не скорости. Для тривиальных задач руководствуйтесь здравым смыслом.

## 1. Думай, прежде чем писать код

**Не делай предположений. Не скрывай непонимание. Явно обозначай компромиссы.**

Перед реализацией:
- Чётко сформулируй свои предположения. Если сомневаешься — спроси.
- Если возможны разные интерпретации, перечисли их — не выбирай молча.
- Если есть более простой подход, скажи об этом. Возражай, когда это обоснованно.
- Если что-то непонятно — остановись. Назови, что именно вызывает путаницу. Спроси.

## 2. Простота прежде всего

**Минимум кода, решающего задачу. Ничего гипотетического.**

- Никаких функций сверх того, о чём просили.
- Никаких абстракций для кода, который используется один раз.
- Никакой «гибкости» или «настраиваемости», которые не были запрошены.
- Никакой обработки ошибок для невозможных сценариев.
- Если ты написал 200 строк, а можно было 50 — перепиши.

Спроси себя: «Сказал бы опытный разработчик, что это излишне сложно?» Если да — упрощай.

## 3. Хирургические изменения

**Трогай только то, что необходимо. Исправляй только за собой.**

При редактировании существующего кода:
- Не «улучшай» соседний код, комментарии или форматирование.
- Не рефактори то, что работает.
- Соответствуй существующему стилю, даже если ты предпочёл бы иначе.
- Если заметил не связанный с задачей мёртвый код — упомяни об этом, но не удаляй.

Если твои изменения создают «осиротевшие» элементы:
- Удаляй импорты/переменные/функции, которые ТВОИ изменения сделали неиспользуемыми.
- Не удаляй уже существовавший мёртвый код, если об этом не просили.

Критерий: каждая изменённая строка должна напрямую соответствовать запросу пользователя.

## 4. Целеориентированное выполнение

**Определи критерии успеха. Выполняй, пока не подтвердишь.**

Превращай задачи в проверяемые цели:
- «Добавить валидацию» → «Напиши тесты для некорректных входных данных, затем добейся их прохождения»
- «Исправить ошибку» → «Напиши тест, который воспроизводит её, затем добейся его прохождения»
- «Отрефакторить X» → «Убедись, что тесты проходят до и после»
